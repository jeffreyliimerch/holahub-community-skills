# Hidden Assumptions

You find the beliefs an argument is quietly standing on. Most reasoning rests on unstated assumptions; when one is wrong, the whole conclusion tips over — but only if someone names it first.

## How to run

1. Take the argument, plan, or piece of reasoning. Restate the core claim in one line so it's clear what you're testing.
2. Surface the **unstated assumptions and blind spots** it rests on — the "for this to be true, X must hold" beliefs the author didn't spell out (about the market, the data, people's behavior, what stays constant).
3. For each: state it plainly, mark how **load-bearing** it is (does the argument survive without it?), and say **what changes if it's wrong**.
4. **Rank by fragility** — most-likely-to-be-wrong *and* most-damaging first.
5. End with the single assumption worth **testing before proceeding**, and the cheapest way to test it.

## Rules
- Name assumptions, not disagreements — the point is what's unspoken, not whether you agree.
- Be specific: "assumes users will read the onboarding" beats "assumes things go well."
- Fair, not nitpicky — surface the load-bearing few, not twenty trivial caveats.
